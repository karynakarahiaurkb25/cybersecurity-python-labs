# Лабораторна робота №2. Об'єктно-орієнтоване програмування та аналіз безпеки поштових заголовків

## 1. Загальні відомості
* **Варіант:** №12
* **Тема індивідуального завдання (Завдання 2):** «Аналізатор заголовків електронної пошти та фішингових індикаторів»

---

## 2. Установлення залежностей та налаштування середовища
Для ізоляції залежностей використовується віртуальне середовище Python:

```powershell
# 1. Створення та активація віртуального середовища (з кореня проєкту)
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# 2. Встановлення необхідних бібліотек
pip install -r requirements.txt

labs/lab02/
├── __init__.py
├── task01.py                   # Завдання 1: Класи User, Admin, Session, AuditLog, UserAccount
├── email_analyzer.py           # Завдання 2: CLI-утиліта аналізу поштових дампів
├── main.py                     # Диспетчер запуску режимів demo та analyze
├── README.md                   # Документація лабораторної роботи
└── data/
    └── data_v12/
        ├── mail_headers.log          # Вхідний файл: дамп поштових заголовків (Message-ID, From, Return-Path, Received, Subject, Reply-To)
        ├── suspicious_keywords.txt   # Вхідний файл: словник стоп-слів для пошуку фішингових тем
        └── phishing_report.csv       # Вихідний звіт: результати аудиту листів та скоринг ризиків

```

## 3. Приклади запуску demo й analyze

* python -m labs.lab02.main demo

* python -m labs.lab02.main analyze --mail-log labs/lab02/data/data_v12/mail_headers.log --suspicious-keywords labs/lab02/data/data_v12/suspicious_keywords.txt --out-csv labs/lab02/data/data_v12/phishing_report.csv

## 4. Oпис параметрів CLI
* --mail-log (обов'язковий): шлях до текстового файлу з дампами повідомлень (mail_headers.log).
* --suspicious-keywords (обов'язковий): шлях до словника слів-маркерів (suspicious_keywords.txt).
* --out-csv (необов'язковий): шлях до вихідного звіту. За замовчуванням: labs/lab02/data/data_v12/phishing_report.csv.
* --debug (прапорець): вмикає детальний журнал логування у терміналі.

## 5. Поведінка при помилках
* Якщо вхідні файли відсутні або заблоковані, програма фіксує критичну подію через стандартний модуль logging і коректно завершує процес із кодом 1, запобігаючи витоку структури системи через службовий стек помилок (Traceback).

* Якщо окремі заголовки у повідомленні відсутні, парсер підставляє значення за замовчуванням, не зупиняючи аналіз решти дампа.

* У разі введення помилкових чи неповних аргументів модуль argparse виводить підказку про використання.
